# Final experience and screen contracts

## Global navigation

Slim left rail: Overview, Environment, Rehearsals, Runs. Bottom: Documentation, mode, operator session if enabled. Report and evidence views are contextual routes, not more primary navigation.

Routes: /, /environment, /rehearsals, /rehearsals/:scenarioId, /runs, /runs/:runId, /runs/:runId/report, /compare?left=...&right=..., /docs, /operator/login (local only).

## Visitor flow

1. Land on Overview. Read one sentence and see a concrete latest result with persistent 'Recorded run' label and timestamp.
2. Click 'Explore rehearsal'. Open the S01 run with its timeline and failure/recovery explanation.
3. Inspect 'Certificate served differs from certificate deployed'. Open linked handshake events and compare fingerprints.
4. Open the environment to see the affected caller -> callee relationship.
5. Download JSON evidence or open printable report. Access documentation and source link if configured.

No signup wall, fake 'Run' button, auto-playing typing effect, or onboarding carousel. In viewer mode use 'Explore recorded run', never 'Start rehearsal'.

## Operator flow

1. Open local deployment and sign in. Persistent 'Live local lab' badge.
2. Environment page checks readiness: controller, issuers, sample services, worker heartbeat, baseline TLS probes.
3. Choose scenario; review planned fault, affected services, expected failed probes, maximum duration, and cleanup sequence.
4. Click 'Start rehearsal'. The one review screen is the execution confirmation; do not add repeated dialogs.
5. Show accepted run immediately, stream persisted events. Navigating away does not cancel execution.
6. Show recovery phase, then outcome and assertion summary. For failure offer evidence and reset guidance.
7. Compare compatible runs, export evidence, or reset if needed.

## Screens

### Overview

Title 'Rehearse the change.' Subtitle states product purpose in one short sentence. Top-right primary action depends on mode. Large main panel: latest run's affected trust path and observed result. Adjacent narrow panel: environment status and scenario scope. Lower section: three scenario rows and recent runs. Do not fill the page with summary-stat cards or meaningless health scores.

### Environment

Show browser/gateway -> orders -> ledger as a left-to-right dependency diagram, with caller trust and callee issuer visible. Diagram nodes are buttons selecting a details panel; also provide an accessible edge table. On small screens use stacked service rows. Distinguish configured issuer, deployed certificate, and observed served certificate. Never conflate them.

### Rehearsal detail

Problem statement, four-step plan, expected evidence, limits, and mode-appropriate action. Explain which failures are expected. No setting for target hostname or shell commands.

### Run detail: principal product screen

Header: scenario, run ID, actual timestamp, mode, lifecycle, outcome. Main 8/12-width area: sequence of named phases and time-ordered observations. Right 4/12: assertions and affected services. Lower tabs: Evidence / Measurements / Recovery. Clicking any assertion opens its supporting events. Keep terminal-like raw logs behind a disclosure; human-readable observations are primary.

Elapsed timings derive from persisted timestamps/worker monotonic durations, not UI timer estimates. Reconnecting shows last known state and stale badge until reconciled.

### Report

Run summary, versioned environment, scenario version, methodology, assertions, measurements/sample denominators, recovery, limitations, evidence references. Print cleanly on A4 with repeated table headers and no clipped content. JSON is the canonical export; PDF generation library is not required for V1.

### Compare

Side-by-side compatible runs. List differing observations and sample counts; no claim of statistical significance. If fixture/live provenance differs, display both labels prominently. Never aggregate unrelated scenarios into a score.

## State copy

- No runs: 'No rehearsals yet. Start with certificate reload validation.'
- Controller offline: 'Lab controller unavailable. Live rehearsals are disabled.'
- Needs reset: 'Recovery did not finish. Reset and verify the baseline before another run.'
- Insufficient samples: 'Inconclusive: not enough probe evidence to evaluate this assertion.'
- Recorded: 'Recorded example. These results were not generated by this deployment.'
- Service auth rejection expected: 'Connection rejected as expected. Security assertion passed.'

Destructive/live actions require genuine operator authority. URL navigation never starts or resets a run.
